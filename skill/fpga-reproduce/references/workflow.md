# 提示词工作流与排错

## 1. 建立接口契约

可复制提示词：

> 工程根目录为【路径】，板卡为【板卡完整型号/器件】，Vivado/Vitis 为【版本】，运行环境为【本工程使用 standalone 裸机；复用时填写实际环境】，系统时钟为【频率及来源】。请读取现有源码、BD、XDC、软件和寄存器表，画出数据/控制路径，列出时钟域、复位极性、地址范围、缓存所有权、数据格式、算法部署位置与输出判据。每项附文件依据；区分当前源码、历史记录和实际加载产物。未知项保留未知。

本案例观察：PL 做采集、VAD/TDOA 和控制；ARM 做 YuNet 与视觉说话检测；PC 串口收图不执行推理。划分依据是代码路径，不是模块名字或宣传文字。其他项目应重新从代码确认。

## 2. 判断需要重建什么

可复制提示词：

> 本次改动为【改动列表/差异】。请逐项指出影响 RTL/BD/IP/XDC、bit/XSA、平台/BSP、ELF、权重、主机工具中的哪些部分。给出必要构建顺序和可观测验收点；不执行发布。重点检查 GUI 参数是否覆盖 HDL 默认值、工程是否引用其他目录旧文件、调试配置是否加载缓存 bit，以及 ELF 地址是否变化。

| 变更 | 必须考虑的更新链 |
|---|---|
| RTL、BD 参数、IP、XDC | 刷新模块/输出产品 → 综合 → 实现 → 时序/DRC/未约束路径 → bit → 含 bit XSA → 平台/BSP/应用 → 调试 bit → 重新初始化板卡 |
| 纯 ARM 代码或编译宏 | 同步实际应用源文件 → ELF → 新符号/日志 → 重新启动并加载权重；接口契约变化则同时重建硬件 |
| 权重 | 文件来源/许可/格式/尺寸核对 → 与算法契约匹配 → 真实地址加载；结构变化另评估代码与存储 |
| PC 接收工具 | 重启接收进程 → 协议/CRC/格式检查；只有协议改变涉及发送端时才更新对应端 |

本案例：6000 门限及安装方向改动在 RTL，旧 bit 不会因此改变；10 帧窗口在 ARM，不能只重新烧 PL。不要将此例的数值机械移植到新算法。

## 3. 以可观测证据定位

可复制提示词：

> 现象为【现象】，输入条件为【条件】，日志/寄存器/波形为【材料】。请按“触发条件 → 可能原因 → 最小检查 → 通过判据”给出定位流程。先确认实际 bit/ELF 与源码对应，再检查数据有效性，最后讨论模型效果。所有准确率、延迟和时序结论都标出证据来源，未测项目不填写估计值。

| 触发条件/观察来源 | 最小检查与通过判据 | 适用边界 |
|---|---|---|
| RTL 修改后行为没变；曾有调试 bit 缓存 | 比较实现 bit、XSA 内 bit、调试 bit 的 SHA-256；核对 BD 参数、构建时间、板上版本寄存器和实际加载日志 | 同版本寄存器并不能证明参数相同；哈希不能证明已经加载 |
| 重编 ELF 后卡在等待或权重错误 | 在当前 ELF 的等待函数设断点，读当前符号/启动日志，加载对应尺寸的两份权重并设置当前 ready 地址 | 不复制本例历史地址；更换运行环境后应重新核对内存访问与加载方式 |
| LED 正确但相机转向相反 | 分开检查麦克风坐标、LED 位序、PWM 偏移符号、舵盘中位及端点，先单方向、后八方向 | moving/settled 是指令状态，没有实物位置反馈；不能证明无堵转/发热 |
| 后方无法对准 | 比较舵机可达角范围与目标角；明确定义最近端点或其他产品策略 | 270° 舵机从中位无法覆盖完整 360°，软件不能消除机械限制 |
| 噪声误触发/远处不触发 | 同环境分别采背景/说话能量，检查绝对阈值、动态噪声底、进入/退出连续次数 | 本例启动 max(6000,noise×2)、退出 max(3000,noise) 不是通用阈值；能量 VAD 不识别说话者 |
| 收到图但无分数 | 区分原始预览标志、找到脸、连续新鲜帧、推理完成；本例 flags=2 是测试图 | 测试图不能证明视觉模型通过 |
| 得到分数但未振动 | 查声音证据、运动编号、锁定、稳定、结果时效、重复提交及分数阈值 | 本例 120 秒规则是延后提醒，不代表实时性能；10 帧至少 1 帧 VAD 不等于准确率 |
| 仿真命令成功但功能不对 | 同时检查退出码、FAIL/FATAL 和明确 PASS；本例失败任务调用 $finish，可能返回 0 | PASS 覆盖范围取决于 testbench，不能证明全功能 |
| WNS 为正但接口偶发异常 | 检查报告的未约束路径、I/O delay、时钟/CDC、复位、实物信号 | 本工程历史报告已说明部分外设时序未完整约束 |

## 4. 从一次测试形成可复用记录

使用报告模板，记录条件、原始日志、输入/产物哈希、通过判据和未通过项目。同一条件下比较改动前后；不要把合成输入、仿真或文件检查包装成现场准确率。提交协作记录时保留真实提示词、回复和本人决定；此处模板只说明今后如何记录，不冒充历史对话。
