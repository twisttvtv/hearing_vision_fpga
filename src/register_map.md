# AXI 寄存器与结果提交

默认基址 `0x43C00000`，窗口 512 KiB，32 位对齐访问。时基为 100 MHz 系统周期，64 位运行计数按高→低→高读取，确认两次高位一致。音视频元数据在释放前保持稳定，RAM 为同步读接口，AXI 模块已处理延迟及两个 16 位元素打包。

| 偏移 | 内容 |
|---|---|
| `0x00` / `0x04` | ID=`0x4D434156` / version=`0x00030000` |
| `0x08` | bit0 视频 ready，bit1 音频 ready，bit2 摄像头初始化完成 |
| `0x0C` | 写 bit0 释放最旧视频，bit1 释放最旧音频；只在复制完成后写 |
| `0x10` / `0x14` | 系统时钟 / 麦克风采样率整数部分 |
| `0x18` / `0x1C` | 高 16 位视频高度、低 16 位宽度 / 每音频块样本数 |
| `0x20` | 视频帧序号 |
| `0x24` / `0x28` | 帧首像素采集时间低/高 32 位 |
| `0x2C` / `0x30` | 视频丢帧/坏帧数 |
| `0x34` | 音频块序号 |
| `0x38` / `0x3C` | 音频块首样本时间低/高 32 位 |
| `0x40` / `0x44` | 音频块首样本全局索引低/高 32 位 |
| `0x48` | 音频缓存满导致的整块丢弃数 |
| `0x4C` / `0x50` | 当前系统计数低/高 32 位 |
| `0x60` | bit0 测试 UART FIFO 可写，bit1 未发空，bit2 启用测试预览 |
| `0x64` | 向测试 UART 写入低字节，需 WSTRB[0]；关闭或满时返回 SLVERR |
| `0x70` | bit0 VAD，bit1 方向有效，bit2 PWM 正在移动，bit3 已稳定，bit4 视角锁定，bit5 当前方向匹配锁定目标 |
| `0x74` | [2:0] 稳定方向，[10:8] 舵机目标方向，[31:16] 原始 CORDIC 角度 |
| `0x78` | 脉宽或目标变化时递增的运动编号 |
| `0x7C` | 控制：bit0 视角锁定；bit1 提交影子结果；bit2 采集期间的 VAD 候选证据。读回仅含锁定位 |
| `0x80` | 视觉分数影子值 0..1000 |
| `0x84` | 采集窗口的运动编号影子值 |
| `0x88` / `0x8C` | 对应中心帧采集时间影子值低/高 32 位 |
| `0x90` / `0x94` | VAD hop 能量低 32 / 高 16 位 |
| `0x98` / `0x9C` | VAD 噪声底低 32 / 高 16 位 |
| `0xA8` | 四路每次共同更新的系统周期数，默认 2048 |
| `0xAC` | 已触发提醒数 |
| `0xB0` | 中心帧序号影子值 |
| `0xB4` / `0xBC` | 结果有效期上限的系统时钟周期数低/高 32 位，默认 12000000000（100 MHz 下 120 秒） |
| `0xB8` | 最后一次结果提交的条件标志，见下文 |
| `0xC0` / `0xC4` | 最近一次提交时，距结果对应中心帧采集时刻的时间间隔低/高 32 位（单位：系统时钟周期）；未来时间戳记录为全 1 |
| `0x20000..0x3C1FF` | 视频 RAM：320×180 个 RGB565，低半字在前 |
| `0x40000..0x403BF` | 音频 RAM：480 个有符号 PCM16，低半字在前 |

方向 0..7 为右、右上、上、左上、左、左下、下、右下。该八方向是麦克风局部坐标，安装后仍需核对云台方向映射。

舵机模块更新不改变寄存器地址或位定义。现在只有 servo0（J3/T19）的 270° 水平舵机参与运动，servo1（J5/R18）恒为低；moving/settled 不再包含俯仰轴运动。方向失效后先保持位置，连续空闲约 240 秒才回中；因此 direction_valid=0 并不表示已回中或停止输出 PWM。空闲回中造成的脉宽变化同样递增 motion_epoch。moving/settled 仍是指令状态，没有机械位置或堵转反馈。

结果提交顺序：保持锁定，依次用完整 32 位字写 `0x80`、`0x84`、`0x88`、`0x8C`、`0xB0`，最后写 `0x7C` 的提交位，原子地触发条件检查。CPU 是唯一写入者。带声音证据且保持锁定的提交值为 `7`；不带声音证据为 `3`。完成后写 `0` 释放锁定。

`0xB8`：bit0 结果具备提醒资格，bit1 分数≥500，bit2 结果时间戳不在未来且时间间隔未超过有效期上限，bit3 运动编号一致，bit4 视角条件通过（舵机稳定且未运动；当前方向匹配，或允许在无有效当前方向时沿用锁定目标），bit5 附带采集期间 VAD 证据，bit6 当前 VAD 状态（默认仅供观察，不再是必需条件），bit7 与上一条提交的帧序号/运动编号组合不同，bit8 提交前已锁定。只有 bit0、bit1 同时为 1 才触发提醒。bit6=0 现在也可以提醒；该标志不表示完整音视频模型置信度。

所有影子字段必须完整字写；控制和释放使用最低字节选通。读取空 RAM 或未对齐地址返回 SLVERR，未映射地址返回 DECERR。轮询 ready 后再读 RAM，不以读取空 RAM 等待数据。复位或重新烧写 PL 后应重新启动 ARM，避免跨复位拼接数据；总线事务期间复位仍可能导致 CPU 异常。


## 测试串口图片类型（ARM/收图工具）

增加原始测试图，未改 AXI 地址或 FPGA 位定义。64 字节 MLIVE001 头中偏移 48 的 flags=2 表示测试图，框/track/线上的占位分数为 0，接收端将分数解释为无结果；flags=0/1 保留视觉结果含义。ARM phase=5 是首张测试图发送阶段；不是新的 AXI 寄存器。传输完成后重新采集连续 10 帧（MODEL_LIVE_FRAMES=10），不跨发送间隙拼接窗口。

预览模式的已确认声音触发现在会锁存为一次任务，在等待转向期间最多保留 10 秒且必须匹配目标方向；不改变 0x70 的实时 VAD/方向位，也不替代 0x7C 提交时的采集声音证据。声音结束不再单独取消已触发任务的视觉计算。

## 较宽松的延后提醒规则

RTL 默认 RESULT_MAX_AGE_TICKS=120×CLK_FREQ_HZ、REQUIRE_LIVE_SOUND=0、ALLOW_UNKNOWN_DIRECTION=1。分数≥0.5、采集声音证据、运动编号一致、非重复和提交时锁定等条件保留。当前声音结束不再单独否决提醒；没有可靠当前方向时允许沿用同一锁定视角，但出现有效的其他方向时仍否决。舵机必须稳定且 servo_moving=0，未放开运动过程中的提醒。振动脉冲仍约 300 ms。

这是延后处理结果的提醒，不再表示说话事件发生在最近两秒内；实际延迟仍需记录和评价。未知方向的容许会放松来源一致性判断，需用本人静默、旁人说话及画外声音测试误提醒。

结果时效寄存器采用 64 位计数：结果有效期上限=(0xBC<<32)|0xB4，最近一次提交的结果时间间隔=(0xC4<<32)|0xC0。该时间间隔等于提交时系统时间减去结果对应中心帧的采集时间；计数值除以系统时钟频率得到秒数。提交的时间戳不在未来、且时间间隔不超过有效期上限时，时效检查通过；它是触发提醒所需的条件之一。默认 120 秒时应读到 0xB4=0xCB417800、0xBC=2。这些只读项对应当前发布 RTL。board/artifacts/ 已提供原 integrate 工程配套的 bit、XSA 和 ELF，使用现有配套文件无需先重建。当前 ARM 视觉窗口为 10 帧，至少 1 帧有效 VAD 证据；若修改 RTL、接口或软件配置，再更新对应硬件及应用。
